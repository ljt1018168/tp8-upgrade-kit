# TP5.1 → TP8 上线部署与灰度回滚通用要点

> 自真实迁移项目的部署实践**抽象重写**，只保留可复用的流程与检查项，
> 所有域名/账号/密钥一律以占位符表示。

## 核心策略：双库并行 + 入口切换 = 秒级回滚

- 旧项目（PHP 7.4 + TP5.1）**原地保留、零改动**，新项目部署到独立目录。
- 新旧各自独立 PHP-FPM 池（不同版本 PHP 并存），nginx upstream 指向新池即上线，
  切回旧池即回滚——回滚不依赖任何代码操作。
- 打包排除：`.git`、`runtime`、`.env`、旧框架快照（`vendor.tp51/`、`thinkphp.tp51/`）、
  IDE/工具目录；打包后**校验包内不含敏感文件**再上传。

## 阶段化步骤（T = 上线日）

### T-3 代码冻结与打包
- 确认无人在改代码；清理调试残留（Demo 控制器、var_dump、测试路由）。
- 移除 Demo 类控制器前先备份，并确认路由/权限表无引用。

### T-1 目标机环境准备
- 按 composer.json + 实际运行需要安装 PHP 与扩展，用 `check_env.php` 逐项自检。
- FPM 关键参数：`request_terminate_timeout` 必须大于最长导出/批处理耗时；
  `memory_limit`、`upload_max_filesize`、`post_max_size` 按业务峰值设置。
- 目录权限最小化：`runtime` 与少量上传/下载目录可写即可，**不要把 public 设 777**。

### T-1 生产 .env
- 逐项核对环境切换的隐藏耦合：`APP_ENV=production` 可能同时切换支付/短信等真实接口、
  业务分界常量；且**不会自动关 debug、不会自动切数据库**（取决于配置写法）。
- `.env` 权限收紧（如 640，属主为运行用户）。

### T-0 部署与初始化
1. 解压到新目录，不动原项目。
2. `composer install --no-dev --optimize-autoloader`（用已提交的 lock）。
3. 清空 runtime（不要带本地缓存上线）。
4. **清 Redis 历史会话**：TP8 的 session key 结构与 TP5.1 不同，旧会话必然失效，
   主动清理并预告用户重新登录，避免「半失效」状态。
5. CLI 冒烟先行（不经过 HTTP，确认框架能起、DB/Redis 通）。

### T-0 nginx 配置与验证
- 伪静态生效后必须实测：受保护路径期望 302/200；**返回 nginx 默认 404 页说明伪静态未生效**。
- 静态资源路径单独验证，确认没有被 rewrite 吃掉。
- 安全兜底规则（`^~` 前缀匹配优先于 rewrite，请求不进入框架）：
  ```nginx
  location ~* ^/(runtime|.*\.log) { return 404; }
  location ~* /\.(env|git) { return 404; }
  ```

### T-0 预发验证（切流前）
- 未登录态 + 真实会话两种身份各跑一遍核心链路（登录、首页、核心写操作、导出）。
- 鉴权链路必须用真实会话验证——未登录态下所有路径统一 302，看起来「一致地正常」。

### T-0 灰度切流
- 按 5% → 20% → 50% → 100% 递进（nginx 权重或按用户分组）。
- 每档观察：5xx 率、登录成功率、SSO 回调、DB 写入正确性、导出文件可打开性、缓存命中率。
- 熔断线示例：`5xx 率 > 0.5%` / `登录成功率下降 > 1%` / `核心写操作失败` → 立即切回。

### 任何时刻：回滚
- nginx upstream 切回旧 FPM 池即完成；数据层若有新写入，按预案单独评估。
- 回滚预案在部署前（而非出事后）写好并演练。

### T+1 ~ T+7 上线后
- 日志目录历史文件迁出 web 根（治本），同时改代码锚定路径；顺序：
  **① 改代码锚定路径 → ② 删历史文件 → ③ 加 nginx 规则**（颠倒会做两遍）。
- 持续观察弃用/降级日志清单，按收敛路线逐步移除兼容层降级规则。

## 上线门禁清单（合并/发布前必过）

- [ ] `php docs/check_env.php` 全绿
- [ ] 全站回归无新增失败项，失败项全部定性
- [ ] `APP_DEBUG=0`、`APP_TRACE=0` 实测确认
- [ ] 包内无 `.env`/密钥/日志/旧框架快照
- [ ] vendor 完整性核验通过（未 hack 框架源码）
- [ ] 真实会话人工登录一次（不能用假 code 判定 SSO 可用）
- [ ] 回滚预案就绪（旧池可切、数据写入影响已评估）
